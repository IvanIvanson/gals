Get started with GALS

View on GitHub

GALS (Grid Application Layout Systems) is a powerful, feature-packed frontend toolkit. Build anything—from prototype to production—in minutes.

Every class is also published as machine-readable reference — llms.txt and gals-classes.json — so ChatGPT, Claude or Copilot generate real GALS markup instead of inventing Bootstrap classes. How it works ↓

See it work

Everything below is plain HTML with GALS classes — no React, no build step. Click to try.

What does a column class look like?
class="pt-6 pt-s12" — 50% on desktop, full width below 770px. GALS has no .col-* classes.
How many classes are there?
186 classes and 8 design tokens, all documented in gals-classes.json.
Do I need a build step?
No. One <link> and one <script> tag and you are building.

Quick start

Get started by including GALS’s production-ready CSS and JavaScript without the need for any build steps. See it in practice with this GALS CodePen demo.

1. Create a new index.html file in your project root. Include the <meta name="viewport"> tag as well for proper responsive behavior in mobile devices. Place the <link> tag in the <head> for our CSS, and the <script> tag for our JavaScript bundle before the closing </body>.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <title>Galsdemo</title>
  <style>*,*::before,*::after{box-sizing:border-box}</style>
  <link rel="stylesheet" href="./gals/gals.css">
</head>
<body>
  <h1>Hello, world!</h1>
  <script src="./gals/gals.js"></script>
</body>
</html>

2. CSS.

Copy-paste the stylesheet <link> into your <head> before all other stylesheets to load our CSS. To ensure that the GALS styles do not interrupt the styles that you will define. 

<link rel="stylesheet" href="./gals/gals.css">

3. JS.

Place one of the following <script>near the end of your pages, right before the closing<body> tag, to enable them. 

<script src="./gals/gals.js"></script>

jsDelivr CDN

You can load GALS directly from jsDelivr — no download, no build step. Just point to the cdn/ folder in the repository.

<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/IvanIvanson/gals@v1.2/gals-main/cdn/gals.min.css">
<script src="https://cdn.jsdelivr.net/gh/IvanIvanson/gals@v1.2/gals-main/cdn/gals.min.js"></script>

Both links are pinned to the v1.2 tag, which jsDelivr caches forever — the file you ship today is the file you ship next year. To move to a newer release, change the tag in both URLs. @main also works and always serves the latest commit, but it can change under you between deploys.

Built for AI

GALS is written to be read by a model, not only by a person. Three machine-readable files ship with the site, and each one is checked by the test suite, so a model is never handed a class that does not exist.

  • llms.txt — the whole framework as plain text, small enough for a context window.
  • llms/gals-classes.json — 186 classes and 8 design tokens as data: selector, CSS, parent and breakpoint flags, plus a doesNotExist list and replacement hints.
  • AI_PROMPT_TEMPLATE.md — the same prompt shown below, as a file.

The JSON is generated from gals.css itself and the test suite fails if the two drift apart. It also carries a doesNotExist list (.row, .col, mt-*, mb-*) — the Bootstrap and Tailwind habits a model falls back to by default — so a generated answer can be checked against real mistakes instead of plausible ones.

Ask AI the right way

Copy this prompt template, paste it into ChatGPT, Claude, GitHub Copilot or Cursor, and replace the text in [SQUARE BRACKETS] with your task.

Act as an experienced frontend developer specializing in the GALS framework.

Task:
Create a [COMPONENT / PAGE / LAYOUT] that does the following: [DESCRIBE THE FUNCTIONALITY, e.g. "a responsive product card with an image, title, price and a 'Buy' button"].

Strict constraints and rules:
1. Framework: use ONLY GALS classes. Do not use Bootstrap, Tailwind or other libraries.
2. Grid: the structure is .container > .container-block with a pt-N column class. GALS has NO .row and NO .col classes, and pt-N classes only apply inside .container.
3. Box model: GALS applies border-box inside .container. Also add a global reset in your page: *, *::before, *::after { box-sizing: border-box; }. Give flex columns min-width: 0 when they contain long content.
4. Columns: pt-1 .. pt-12 set width in twelfths (pt-6 = 50%). pt-N is a COLUMN width, not padding. GALS has no spacing utilities except .padding-lg.
5. Responsiveness: override a column per breakpoint with pt-{bp}N, where bp is xl (1440px+), l (max 1439.98px), m (max 1025px), s (max 770px), xs (max 425px), xxs (max 375px). Example: class="pt-6 pt-s12" is 50% on desktop and full width from 770px down. Hide on a breakpoint with pt-{bp}-d_n.
6. Styles: for custom styles reuse the GALS tokens: var(--accent), var(--ink), var(--paper), var(--ok), var(--warn), var(--err), var(--line), var(--gridmultiplyConst).
7. Components: header, table, btn, alert, card, accordion, carousel, dropdown, modal, menu, tabs, pagination, popover, progress, loader, skeleton, icon, media, input, select, range, checkbox, radio, switch. If a class is not in this list, do not invent it — write plain CSS instead. Functional requirements: dropdown needs popovertarget + popover + accessible positioning/arrow keys; modal needs dialog.showModal(); tabs need input/label/panel in order; menu needs .icon-menu + .menu.menu-collapse with aria-controls/aria-expanded.
8. Output: provide ONLY valid HTML. Include <link rel="stylesheet" href="gals/gals.css"> in the <head> and <script src="gals/gals.js" defer></script> before </body>. Make sure all tags are closed and accessibility (ARIA) attributes are used.

Context:
[OPTIONAL: add specific requirements here, e.g. "Use .alert-ok for the success message and .btn-primary for the main action"].
